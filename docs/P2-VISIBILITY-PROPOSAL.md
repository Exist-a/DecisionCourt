## 1. 先澄清一个提法（本方案的前提）

原诊断 §2.4 的措辞是"每一方只能看到对方的**结论**，看不到对方的**论证**"。**逐行读代码后这个提法需要修正**：

| 对手的什么 | 当前对方可见？ | 依据 |
|---|---|---|
| 公开发言**正文**（`Content`，200–500 字，含完整论证） | ✅ **可见** | `renderTranscriptLine` 取 `ActionType + Content`；`withArgumentSummaryText` 也带对方最新发言全文 |
| 引用证据 ID（`evidence_refs`） | ✅ 可见 | M1 后来自投影后 `WorkingMemory` |
| 立场 / 置信度（`stance` / `confidence`） | ✅ 可见 | 同上（M1 新增了这条可见面） |
| **推理链（`reasoning`）** | ❌ **不可见** | D13-A 白名单：`model.Message.Metadata` 永不进提示词 |
| **私有策略笔记**（strategy_note / opponent_weakness / self_correction / evidence_eval） | ❌ 不可见 | SQL 可见性过滤 + `PrivateMemory` 只送回本人 |

**所以 P2 的真正问题不是"要不要给论证"（论证已在公开发言正文里），而是：**
> **要不要进一步给对方的"推理链 / 内心戏"？**

---

## 2. 三个选项

### 选项 ① 维持现状（推荐）

对方可见 = 公开发言正文 + 立场 + 置信度 + 引用证据；不可见 = `reasoning` 与私有笔记。

- **优点**：保住 D13 的核心隔离不变量（有注入式回归测试钉住）；对抗靠"论证对论证"，语义完整
  —— 双方手里的公开发言正文本身就是完整论证，不存在"只能结论对结论"的缺陷。
- **代价**：双方无法针对对方**未说出口**的推演提前设防（这正是"对抗真实性"的来源，不一定是缺点）。
- **变化量**：0（现状即此）。

### 选项 ② 扩大到"结构化论证摘要"（中间态）

在保持 `reasoning` 不可见的前提下，让对方额外看到一份**系统抽取**的论证结构：
争议焦点、主要论据条目、已引用/被反驳的证据集合（其中部分元素 M1 后已可见）。

- **优点**：提升"论证对论证"的针对性；仍然不暴露原始推理链，隔离契约不破。
- **代价**：需新增一层"从对方发言抽取结构"的逻辑（又是一处 LLM 调用或规则抽取），
  且**抽取本身可能失真/夹带**——要防它成为 reasoning 的间接泄漏通道（等价于 M5 的联动风险）。
- **验收**：必须证明"抽取产物 ≠ 对 reasoning 的可还原投影"（难量化）。

### 选项 ③ 完全透明：暴露 `reasoning`（不推荐）

- **优点**：对抗最"深"。
- **代价（为什么不做）**：
  1. 直接推翻 D13 的核心保证（"控辩互不可见推理链"），且该保证有注入式回归测试；
  2. `reasoning` 是"内心戏"——用户侧本就把它当"幕后视角"看（前端策略笔记区），把它喂给对手
     等于让 Agent 互相预判，反而**削弱**对抗的真实性；
  3. **M5 联动变炸弹**：公开 A2A `speech` payload 目前**明文存 `reasoning`**（为审计友好），
     一旦提示词消费 reasoning，"明文"就从审计属性变成泄漏源；
  4. 与 M1 的实施纪律冲突（M1 明确要求新消费方**只读投影后的 `WorkingMemory`**）。

---

## 3. 推荐

**维持选项 ①**。理由：论证已完整可见（见 §1 澄清），当前隔离的价值（对抗真实 + 推理不可被预判）
大于"再看对方内心戏"的边际收益；且选项 ②的收益不确定、验证成本高，选项 ③直接违背 D13/M5。

若确实感到"对抗不够深"，**更该调的是论证质量本身**（P1 主张级接地已落地，可据其指标迭代），
而不是打开推理链。

---

## 4. 若选 ②/③ 的强制前置（记录备查）

1. 必须先做**真实庭审 A/B 同题对跑**（对照庭审走向 + 发言质量）；
2. 必须补**注入式隔离回归**：断言"未被授权的字段（reasoning / 私有笔记）不出现在提示词里"；
3. 若选 ③，必须先解决 M5（公开 payload 明文存 reasoning）——否则等同主动泄漏；
4. 通过 AGENTS.md §2.1（先讨论后执行）+ §11（docker 业务验证）+ 浏览器实测。
