## 0. 结论（TL;DR）

**"让每一方每一次输出都贴合实际"这个目标，靠改 prompt 的措辞基本达不到。** 决定接地性的是**真实素材在进入模型之前还剩多少**，以及**能否在主张级判断接地**；而这两层在代码里都有硬缺口。措辞只能改变"约束"（别编造、别重复、别越界），改变不了"接地"。

按**决定性**排序：

1. **素材管道**（最致命、最可修）：证据正文被砍到 200 字节（≈66 汉字），调查发现根本没注入（占位符）。
2. **校验粒度**：四道护栏全是**模式级**（正则 / Jaccard / judge），**不能判断"这句话有没有依据"**。
3. **可见面**：转写只给结论（`ActionType` + `Content`），双方看不到对方的论证。
4. **指令层**：`baseRules` 全是**约束**语义，不提供事实。

且 1 与 2 **耦合出恶性循环**：护栏禁止无证据支撑的具体数字，而证据正文只给 66 汉字 → 模型看不到细节、又被禁止补充细节 → 只能输出"损失金额较大"这类**安全但空洞**的话。**这正是"不贴合实际"的直接机制。**

## 1. "贴合实际"的判据是什么

要让"输出贴合实际"成为可执行的目标，先要把它翻译成可判定的形式：

> **输出里每一条事实性主张，都能追溯到 prompt 中提供给它的真实素材**（用户背景 / 证据正文 / 调查发现 / 对方已说的事实）。

这个定义有三个直接推论：

- **素材必须先"进得去"**：模型不可能贴合它看不见的东西。→ 决定性因素之一是**素材管道的带宽**。
- **接地必须"可判"**：否则无法验证、无法回归、无法迭代。→ 决定性因素之二是**校验粒度**。
- **措辞只影响"表达约束"**：它决定"能不能说"，不决定"有没有事实可说"。

## 2. 现状盘点（逐项 + 代码证据）

### 2.1 素材管道（决定性 #1）

| 素材 | 提交/存储上限 | 实际进入控辩 prompt | 折算（中文，UTF-8 3 字节/字） | 证据 |
|---|---|---|---|---|
| 用户背景 `session.Context` | 2000 字符 | 2000（原样） | ≈2000 字 | `api/handler.go` `max=2000`；`prompts.go` `SanitizeShortField(Context, 2000)` |
| **证据正文** | **4096 字符** | **`truncate(content, 200)`（字节）** | **≈66 字** | 提交 `api/handler.go` `max=4096`；展示 `prompts.go` `truncate(e.Content, 200)` |
| **调查发现** | 存 `investigation_findings` 表 | **占位符，从不注入** | **0** | `prompts.go` `buildInvestigationContext` 输出 `[由 ... 注入]` 字样 |
| 对手最新发言 | 全文在 DB | `truncate(opponentLatest.Content, 150)`（字节） | ≈50 字 | `orchestrator.go` `withArgumentSummaryText` |
| 自己上次发言 | 全文在 DB | `truncate(selfLatest.Content, 100)`（字节） | ≈33 字 | 同上 |
| 庭审历史每条 | 全文在 DB | `truncateForPrompt(content, 240)`（字节） | ≈80 字 | `react_runner.go` `buildInitialMessages` |

**两个必须点名的量纲错误**：

1. **证据正文：提交 4096 字符，展示 200 字节。** 两者单位不同（字符 vs 字节），中文下差约 **3 倍**；再叠加"4096 → 200"的数量级差，**一条满额证据对辩手可见度 ≈ 1.6%**。这大概率是历史遗留（提交上限后来放宽、展示上限没跟），不是有意的设计取舍。
2. **截断函数是字节级的**：`truncate` / `truncateForPrompt` 按 `len()` 切字节（后者有 rune 边界回退），只有 300 字发言上限用 `truncateRunes` 按字符切。**同一份代码里两套单位**，中文场景下差 3 倍。

**结论**：控辩双方手里的"实际"素材，在拼进 prompt 时已被砍到只剩骨架。**这是"不贴合实际"的第一来源。**

### 2.2 校验粒度：模式级 ≠ 主张级（决定性 #2）

四道输出护栏，全部是**模式匹配**：

| 护栏 | 判据 | 能判什么 | 证据 |
|---|---|---|---|
| 反幻觉校验 | 正则：案号 / 百分比 / 金额 / "证据N" / `E00X` | "看起来像编造" | `output_validator.go` |
| 新意度 | Jaccard 相似度 > 0.6 | "和自己之前太像" | `react_runner.go` `applySpeakerNoveltyRetryLoop` |
| 立场一致性 | LLM-as-judge | "和自己的信念方向不符" | `react_runner.go` `applySpeakerStanceJudge` |
| 已反驳证据 | 查 `evidence_rebuttal_links` | "引用了已被反驳的证据" | `react_runner.go` `applySpeakerRebuttalRetryLoop` |

**没有任何一道在判断"这句话有没有依据"。** 它们抓的是**表面特征**，不是**主张与素材的对应关系**。所以：

- 一句"因为行业普遍如此"——不匹配任何模式 → 放行（但它同样没有依据）。
- 一句含真实数字、但数字抄错——模式匹配不到 → 放行。
- 一句把证据里的"月薪 8000"说成"月薪 8000 元（证据 E001）"——**能**匹配，但如果它没带 `evidence_refs`，会被拒。

### 2.3 恶性循环（1 × 2 的耦合）

这是最需要被看见的一条因果链：

```
证据正文只给 66 汉字
        ↓
模型看不到细节（不知道那条证据里到底写了什么）
        ↓
反幻觉护栏禁止"无证据支撑的具体数字/金额/案号"
        ↓
模型既不能看、也不能补 → 只能写"损失金额较大""收益存在不确定性"
        ↓
用户读到的是：不假，但空洞 → 主观感受即"不贴合实际"
```

**反幻觉护栏本意是提升真实性，实际效果是把输出推向模糊。** 护栏属于"约束"，约束不等于"接地"——把假话拦住，不等于让真话出现。

### 2.4 可见面：结论级，不是论证级（决定性 #3）

`renderTranscriptLine` 是显式白名单：**只允许 `ActionType` + `Content` 进 prompt**，`Metadata`（含 `reasoning` 推理链）一律不进（D13 信息隔离，防对手偷看推理）。

- 好处：信息隔离成立，双方无法利用对方推理。
- 代价：**每一方只能看到对方的结论，看不到对方的论证**。对方论证里的漏洞，本方**结构上看不见**，也就无法做"论证对论证"的深挖，只能"结论对结论"对冲。

### 2.5 指令层只是约束（决定性 #4）

`baseRules` 14 条规则 + 角色策略，语义全部是**约束**：别编造细节、别引用不存在的证据、别重复、别人身攻击、别附和、别只喊"需要补充证据"。角色策略是"往哪个方向找证据"。

**没有一条在提供事实。** 所以改这套措辞能改善的是**约束维度**（更少幻觉、更少重复），改善不了**接地维度**。这是"改 prompt 试效果"经常感觉在瞎调的根因——**它在调一个不是瓶颈的旋钮**。

### 2.6 同源发现：信念输入也有非接地的兜底

信念引擎的输入是 LLM 评估的证据影响度（`evidence_eval`）；但 LLM 评估失败时会**回落到关键词兜底** `estimateImpact`——一张"好/优/高/快/强"加 0.15、"差/劣/低/慢/弱"减 0.15 的词表（`evidence/service.go`）。这个兜底完全不接地，却直接驱动信念更新与后续所有发言的立场。属于同一类问题（用启发式冒充事实）。

## 3. 修复路线（按决定性排序）

### P0 — 素材管道（收益数量级，优先做）

1. **证据正文展示上限与提交上限对齐**：把 `truncate(e.Content, 200)` 提到与 4096 字符同一量纲（例如按 token 预算给足全文，或至少 rune 级 2000+）；同时把 `truncate` 的**字节语义改为 rune 语义**，消除"提交用字符、展示用字节"的量纲不一致。
2. **真正注入调查发现**：把 `buildInvestigationContext` 的占位符换成 `investigation.Repository.ListBySession` 的真实列表（该函数注释里早已写明预期做法）。让双方手里有**累积的调查事实**，而不是只有本轮 tool_call 的即时 observation。
3. **对手/自己的历史发言放宽**：150/100/240 字节 → rune 级、且给足（对手最新发言应完整可见，这是"回应对方"的前提）。
4. 验收：对同一场真实庭审，对比修复前后 prompt 中素材的**可见字节数**与输出中**具体事实的出现率**。

### P1 — 校验粒度（让"接地"可判）

1. 在现有模式级护栏之外，增加**主张级可追溯性检查**：抽取输出中的事实性主张（数字 / 实体 / 因果句），检查其能否在提供的素材中找到支撑；找不到的降级为"无依据主张"并标记（先观察，不硬拒）。
2. 把该指标做成**可观测**（metric + 文件日志字段），使"接地率"成为可回归的量。
3. 关键：**先"标记 + 度量"，再决定是否硬拒**——避免重演"护栏把输出推向模糊"的副作用。

### P2 — 可见面（产品决策）

是否让双方看到对方的**论证**（而非仅结论）——这是信息隔离与对抗深度的取舍，需用户拍板，不在本分析内擅自决定。

### P3 — 措辞（最后微调）

前三层修好后再动 `baseRules`，否则测到的是噪声。

## 4. 验收标准（DoD）

1. **素材可见性**：同一场庭审的 prompt 中，证据正文 / 调查发现 / 对手发言的可见字节数有明确提升，且单位统一为 rune。
2. **接地可观测**：新增"无依据主张"指标可在 `/metrics` 与文件日志看到。
3. **不退化**：反幻觉护栏的既有测试全部通过（不简化、不删除，见 `AGENTS.md` §3）。
4. **业务验证**：按 `AGENTS.md` §11 起 dev compose，跑一场真实庭审，人工核对输出中具体事实是否来自素材。

## 5. 非目标

- 不做"让 LLM 自己判断自己是否接地"（那是把判据交给被审对象）。
- 不在本项内改动信息隔离策略（P2 单列，需产品决策）。
- 不做多语言 / 多模型适配（先解决中文量纲问题）。

## 8. 新发现（2026-10-10 第 3 轮实跑撞出）：**发言步的 prompt 里没有任何案件素材**

> 这是做流式记账（deferred R18）时顺手撞出来的，**比 §2.1 的"证据正文只给 66 汉字"更根本**：
> 前者是"素材被截断"，后者是"素材压根不在那一层"。

### 现象（代码 + 实测）

- `react_think`（思考步）的输入是 **5,467 – 10,146 token**（system prompt + baseRules + 证据 + 历史）。
- `react_speak_stream`（**真正产出用户读到的发言**那一步）的输入只有 **183–196 token**。
- 根因在 `react_runner.go::streamSpeakContent`：它**故意**用一段全新的极小 system prompt ——
  > 你是一名资深庭审律师。现在请输出一段最终庭审发言（中文）。
  > **重要：忽略之前的对话历史与任何系统协议。**
  并把 user turn 只填 `论点 / 立场 / 置信度`（即上一步的 `out.Reasoning`）。注释写明动机是
  "让 LLM 完全 fresh，避免被之前的 ReAct 对话历史污染输出格式"。

### 影响（为什么比 §2.1 更根本）

- 用户看到的**发言本身**在生成时**看不到证据、背景、对方论点** —— 它只是把思考步的 `reasoning`
  文本**重写**成一段像样的法庭发言。
- 事实细节能出现在发言/判决里，**完全依赖思考步把细节写进了 reasoning**（间接传导），
  而不是"发言时对着素材说"。
- 推论：§7 的素材放宽（证据正文给足全文等）**只作用在思考步**；发言步的接地是"转述保真度"问题，
  不是"素材带宽"问题。一旦 reasoning 被压缩或截断，发言会跟着丢细节。

### 定性

**是有意的设计取舍**（注释写明了动机），不是遗漏。但它与 §1 的判据（每条事实主张都能追溯到素材）
存在**结构性张力**：发言步手里没有素材可追溯。这也解释了"为什么改了 prompt 措辞感觉在瞎调"——
发言步根本不吃那些素材。

### ✅ 决策记录（2026-10-10，用户拍板）：**发言步改为"全量带"**

**决策**：让发言步（`streamSpeakContent`）**带上全量素材**（证据 / 调查发现 / 庭审历史 / 对方论点），
不再只喂 `论点·立场·置信度`。

**用户给出的理由**：正常一轮庭审的预算峰值只有 ~69.4%，**根本达不到 70% 的压缩触发线**
（见 `OBSERVABILITY.md` §8.6 的真实庭审基线），所以"素材变多会被压缩掉"这个担忧在当前不成立；
token 成本可承受 → 没必要为了省 token 而给发言步"预先节食"，直接全量带。

**待实施时的注意点（写下来供实现时对照，尚未动代码）**：

> **轮次归属：未定**（用户只定了方向，没指定放哪一轮）。建议**独立成一个小轮**而不是塞进第 4 轮——
> 第 4 轮是"隔离收口"（投影/M1），本条是"发言接地"，两者的验证方式不同（一个比对庭审走向、
> 一个比对发言里事实的出现率），混在一起会互相干扰回滚。

1. **必须保留原设计的收益**：原实现刻意 fresh 是为了避免 ReAct 的多轮 `action/tool_call` JSON 污染
   最终输出的**格式**（v0.10.1 ADR 0021 的动机）。所以"带全量"要做成**带素材但不带格式噪声**——
   例如把素材整理成明确的"## 案件素材"区段注入，同时**保留**那条"只输出 `{"content": ...}` 一行 JSON"
   的强约束（不能连中间轮次的 action JSON 一起塞进去）。
2. **验收**：A/B 跑**同题**真实庭审，对比（a）发言里具体事实/数字的出现率（b）发言长度分布与 JSON 解析
   失败率（c）整场 token 消耗增量。任一项明显恶化都要回退。
3. **补回归**：目前**没有**任何测试断言"发言步的 prompt 包含素材"；实施时应补一条**注入式**测试
   （往素材里塞一个标记，断言它出现在发言步的 prompt 里），否则下次有人"顺手改回去"不会被发现。
4. **口径联动**：这条与 §3 P2（可见面：是否让双方看到对方论证）**独立**——P2 决定"素材里放不放对方论证"，
   本条决定"放了之后发言步看不看得到"。

**历史选项（保留备查）**：

| 选项 | 做法 | 结果 |
|---|---|---|
| ① 保持现状 + 只加保真约束 | 承认"发言 = 对 reasoning 的转述"，加"不得新增 reasoning 未出现的事实" | 未选 |
| ② 补**精简**素材块 | 只塞"证据清单（ID + 一句话摘要）+ 争议焦点" | 未选（用户选的是更彻底的"全量带"） |
| ③ 只登记不改 | — | 未选 |
