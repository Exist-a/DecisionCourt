## 🎯 核心主题

**v2.8 = LLM Trace 全量 Prompt 持久化开关**

3 个核心收益：

1. **Tri-state 开关可控**：AGENT_GATEWAY_FILE_LOGGER_PROMPTS={off,metadata,full} 让用户 opt-in 完整 prompt 落盘,借鉴 APP_ENV 三态 enum pattern
2. **后向兼容零成本**：omitempty 让旧 log 行 (v2.7 时期) 仍能解析,Run.Input / Output 在 metadata 模式仍是 zero value (前端 RebuttalTraceNode / AgentTraceNode 已有 nil-guard, 不变化)
3. **PII 风险 opt-in**：默认 metadata 保留 v2.7 baseline, 用户需显式设 full 才会把 prompt + output content 落地 (隐私风险在用户侧)

## 🆕 新增功能 (PR-3 commit 汇总)

### PR-3 (1/7): LogEntry 加 4 optional 字段

`backend/internal/agent_gateway/file_logger.go`：

```go
SystemPrompt    string         `json:"system_prompt,omitempty"`     // "system" role 完整文本
InputMessages   []llm.Message  `json:"input_messages,omitempty"`    // user/assistant history
OutputContent   string         `json:"output_content,omitempty"`     // LLM 返回 content 全文
OutputTruncated bool           `json:"output_truncated,omitempty"`   // 是否被 MaxBytes 截断
```

omitempty 关键：metadata / off 模式不填这 4 个字段 → JSON 自动跳过 → 旧 log 行向后兼容零成本。

### PR-3 (2/7): GatewayConfig 双字段 + 三态 helpers

`backend/internal/agent_gateway/gateway_config.go`：

```go
FileLoggerPrompts         string `mapstructure:"AGENT_GATEWAY_FILE_LOGGER_PROMPTS"`        // off|metadata|full
FileLoggerPromptsMaxBytes int    `mapstructure:"AGENT_GATEWAY_FILE_LOGGER_PROMPTS_MAX_BYTES"` // 默认 32KiB
```

新增 helpers:
- `IsFileLoggerPromptsFull()` → `IsFileLoggerEnabled() && FileLoggerPrompts == "full"` — 真正写 4 字段
- `IsFileLoggerPromptsOff()` → 与 `FileLogger=false` 等价,writeFileLog no-op

`Normalize()` 默认 `"metadata"` + 32 KiB。

### PR-3 (3/7): writeFileLog 签名 + 三态分流

`backend/internal/agent_gateway/gateway.go`：

新增参数: `systemPrompt string, messages []llm.Message, content string`

```go
if g.cfg.IsFileLoggerPromptsOff() {
    return // "off" 整个 no-op
}
...
if g.cfg.IsFileLoggerPromptsFull() {
    // 按 FileLoggerPromptsMaxBytes 截断, 防单 entry 撑爆
    entry.SystemPrompt, _ = truncateForLogBytes(systemPrompt, g.cfg.FileLoggerPromptsMaxBytes)
    entry.InputMessages = messages  // 不截断数组 (LLM token budget 已控整体大小)
    entry.OutputContent, _ = truncateForLogBytes(content, g.cfg.FileLoggerPromptsMaxBytes)
    entry.OutputTruncated = sysTrunc || contentTrunc
}
```

2 个调用点 (Complete L310 + StreamComplete L451) 传递 systemPrompt/messages/(流式累积)content。

### PR-3 (4/7): env 读取 + Validate fail-fast

`backend/internal/config/config.go`：AgentGatewayConfig 加 2 字段，Load() 加 2 个 envOrDefault。

`backend/internal/config/validate_file_logger_prompts.go` (NEW):
```go
func ValidateFileLoggerPrompts(v string) error {
    switch v {
    case "off", "metadata", "full":
        return nil
    default:
        return fmt.Errorf("AGENT_GATEWAY_FILE_LOGGER_PROMPTS=%q invalid; must be one of off|metadata|full (ADR 0042)", v)
    }
}
```

`cmd/server/main.go`：与 ValidateAppEnv 同级调用 (P1-7 启动 fail-fast 模式)。

### PR-3 (5/7): parser 字段映射 (后向兼容核心)

`backend/internal/trace/parser.go::entryToRun`：

```go
var input map[string]any
if entry.SystemPrompt != "" || len(entry.InputMessages) > 0 {
    input = map[string]any{
        "system_prompt": entry.SystemPrompt,
        "messages":      entry.InputMessages,
    }
}
return Run{
    ...,
    Input:  input,
    Output: entry.OutputContent,
}
```

**类型兼容**: Run.Input 历史是 `map[string]any` (trace 系统设计), 装 `{system_prompt, messages}` 是最简非破坏映射, frontend 不需要改 type。

`frontend/components/trace/AgentTraceNode.tsx`：

## 🔧 配置默认 + Opt-in 设置

| 模式 | env 值 | LogEntry 行为 | 用户步骤 |
|---|---|---|---|
| **off** (合规) | `AGENT_GATEWAY_FILE_LOGGER_PROMPTS=off` | 完全不写 LogEntry | 启动 fail-fast 校验 |
| **metadata** (默认) | (未设) | 只写 metadata | 零配置 |
| **full** (opt-in) | `AGENT_GATEWAY_FILE_LOGGER_PROMPTS=full` | 写 system_prompt / input_messages / output_content (按 MaxBytes 截断) | 显式设 .env |
| **tune cap** | `AGENT_GATEWAY_FILE_LOGGER_PROMPTS_MAX_BYTES=65536` | 单 entry 64 KiB 上限 | 默认 32 KiB |

---

## ⚠️ PII / 磁盘风险 (call out 给用户)

1. **PII 暴露**: `full` 模式把 evidence.content + message.content 等用户提交的自由文本落地到本地日志文件。**风险等级**: 中-高 (有用户提交身份证号等场景)
2. **磁盘膨胀**: full mode ~5-50KB/entry × 50 calls/trial = **2.5MB/trial**, 一年 ~1GB (1 trial/day)。max-bytes cap 防单 entry 撑爆但不防累积
3. **logs/ 无 retention policy**: 当前项目无 logrotate / cleanup, 长期 full mode 会撑满磁盘。**v2.8 deferred 到 v2.9 PR-X (D4 logs retention)**, 通过新建 `docs/todo/deferred-items-2026-09-21.md` 登记
