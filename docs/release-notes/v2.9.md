## 🎯 核心主题

**v2.9 = 法官判决书"考虑 rebuttal 状态" — 全链路落地**

3 个核心收益：

1. **Verdict.EvidenceAdoption jsonb 落地** — 每条 evidence 的采纳状态 (standing/overturned/withdrawn/adopted) 写入 verdict 表，前端 "证据采纳" 卡显示，颜色 chip + 权重 + 备注
2. **belief_diffs Source=rebuttal trail** — 每个 standing / withdrawn 证据写一条 `belief_diffs` row，phase="verdict", Round=0, Direction=neutral, EvidenceWeight=0 — 让 audit trail 覆盖 "法官判决时忽略 E001" 这条事实
3. **JudgeFinal / Clerk prompt 加 rebuttal 强制规则** — §2.1 用户决策: standing 硬指令 LLM "treat as not submitted", overturned 引用带 caveat, withdrawn treat as not submitted

## 🆕 新增功能 (PR-4 commit 汇总)

### PR-4 (1/8): Verdict schema 加 jsonb EvidenceAdoption

`backend/internal/model/db.go`：

```go
type Verdict struct {
    ...existing 14 fields...
    // v2.9 PR-4 (ADR 0043) §2.1: per-evidence 采纳状态
    EvidenceAdoption *EvidenceAdoptionJSONB `gorm:"type:jsonb" json:"evidence_adoption,omitempty"`
}

type EvidenceAdoptionEntry struct {
    EvidenceID    string  `json:"evidence_id"`     // uuid
    DisplayID     string  `json:"display_id"`      // E001
    Status        string  `json:"status"`          // standing | overturned | withdrawn | adopted
    WeightApplied float64 `json:"weight_applied"`  // 0.0 = hard-ignored, 1.0 = full weight
    Reason        string  `json:"reason"`          // 中文
}

type EvidenceAdoptionJSONB []EvidenceAdoptionEntry
// + driver.Valuer + sql.Scanner (GORM jsonb 持久化)
```

GORM AutoMigrate 自动加 jsonb 列。

### PR-4 (2/8): belief_diffs Source=rebuttal 常量

`backend/internal/model/belief_diff.go`：

```go
const (
    BeliefSrcEvidence   = "evidence"
    BeliefSrcWeaken     = "weaken"
    BeliefSrcAnchorPull = "anchor_pull"
    BeliefSrcStance     = "stance"
    BeliefSrcRebuttal   = "rebuttal"  // v2.9 NEW: 法官判决 trail
)
```

**Trail 用途**: 每个 standing/withdrawn 证据一条 `belief_diffs` row, phase="verdict", Round=0, Direction=neutral, EvidenceWeight=0.0。

**不重算**: verdict 阶段 BeliefA/B 仍是 judge LLM 直接给 (用户 §2.1 决策边界)。

### PR-4 (3/8): BuildAdoptionSummary 纯函数

`backend/internal/courtroom/rebuttal_adoption.go` (NEW)：

```go
type AdoptionSummary struct {
    VerdictAdoption []model.EvidenceAdoptionEntry  // 给 Verdict.EvidenceAdoption jsonb
    BeliefDiffsRows []model.BeliefDiff              // 给 belief_diffs Source=rebuttal rows
    PromptRender    string                          // 给 LLM prompt 的 markdown section
    Counts          AdoptionCounts                  // log + dev observability
}

func BuildAdoptionSummary(sessionID, links, evidences) AdoptionSummary
```

**Latest-wins link 状态语义**: 同一 evidence 多条 link → 取最新 status。
**`adoptionTableMaxRows=200`**: 防止 session 有 500+ evidence 时 prompt 撑爆。
**PromptRender**: markdown 表格按 display_id 排序，含 4 类 status 强制规则。

### PR-4 (7/8): Frontend 证据采纳卡

`frontend/app/verdict/[id]/page.tsx`：

庭审纪要之后、判决书正文之前，新增 `<section>` "证据采纳"：

- 表格 4 列: 证据 / 状态 / 权重 / 备注
- 状态颜色 chip:
  - **standing** → "反驳有效" (bg-rose-900 红)
  - **withdrawn** → "撤回" (bg-stone-700 灰)
  - **overturned** → "已翻盘" (bg-emerald-900 绿)
  - **adopted** → "采纳" (bg-stone-500 中性)
- 底部说明小字: standing/withdrawn LLM 已 hard-instructed 忽略；overturned 可引用带 caveat
- 仅 verdict.evidence_adoption 非空时显示，老 verdict (v2.9 之前) 完全跳过

## ⚠️ Breaking Changes

**无公开 API breaking change**, 但 **Verdict schema 增 1 字段**。详情:

- ✅ 公开 REST API (`GET /api/v1/courtrooms/:uuid/verdict`) 在 EvidenceAdoption 为 nil 时仍返正常 JSON,前端检测 `?.length > 0` 跳过老 card
- ✅ GORM AutoMigrate 自动加 jsonb 列,旧 verdict 行 EvidenceAdoption = NULL 不破
- ✅ 前端老 verdict 页面布局不变 (新 section 在新字段非空时才显示)
- ⚠️ 数据库迁移: GORM AutoMigrate 自动加 `evidence_adoption jsonb` 列, PostgreSQL 不需要 migration script
