## 🎯 核心主题

**v2.7 = Silent Error 黑洞根因 100% 收尾**

3 个核心收益：

1. **Stream parser 根因重写 (PR-1)**: `streamSpeakContent` 用 `scanJSONContentField` 替换 ad-hoc JSON 解析,新增 `\uXXXX` 解码 + 跨 chunk 边界 reassemble + nested object depth tracking + markdown wrap / preamble 中文 prose 兼容,从"边界 case 偶尔 silent fail"变成"边界不可能产生 empty content"
2. **Detached verdict ctx (PR-2)**: `finishTrial` 加 `verdictCtx = context.WithTimeout(Background, 120s)`,JudgeFinalDecision + GenerateVerdict 用 verdictCtx 走 LLM 调用,不被 cancelCall / HTTP ctx cancel 牵连
3. **Retry-on-Canceled hook (PR-2)**: `completeWithCancelRetry` helper 实现 one-shot retry with detached `Background+90s`,`errors.Is(err, context.Canceled)` 才触发;network / parse / DeadlineExceeded 错误不 retry

### 与 v2.6 的关系

| 主题 | v2.6 | v2.7 |
|---|---|---|
| D2 (cross-exam silent content) | 黑洞**变可见**(WARN + REJECT) | 黑洞**根因消除**(parser 重写) |

| 边界 case (`\uXXXX` / 嵌套 / 跨 chunk) | 仍偶尔 silent fail | 不可能 silent fail |
| cancelCall race | fallback 较常见 | detached + retry 二级防御 |

## 🆕 新增功能（PR-1 + PR-2 commit 汇总）

### PR-1 (1/5): scanJSONContentField helper

`backend/internal/agent/react_runner.go`：新增 `func scanJSONContentField(raw string) (string, bool)`：

- 跳前置非 `{`（markdown wrap / 中文前言兼容）
- brace+bracket depth tracking（仅 `depth==1` 匹配顶层 `"content"` key,避免 nested 误判）
- 完整 unquote `\uXXXX` → rune（4 hex digit,失败 verbatim 保留）
- 部分解析 vs 完整解析区分: `complete` true 仅 closing `"` 后是 `,` / `}` / EOF

新增 helpers:
- `isJSONWhitespace(c byte) bool` — scan 中跳过 whitespace
- `isHex(c byte) bool` / `hexNibble(c byte) uint32` — `\uXXXX` 解码辅助

### PR-1 (2/5): unquoteJSONString 增强 `\uXXXX`

之前版本直接吞掉 `\u` 两个字节,LLM emit `\u4e2d\u6587` 时前端拿 literal escape。新版支持 `\uXXXX` → rune 解码。同时非法 `\u`（不足 4 位或非 hex）保留 verbatim,避免吞错。

### PR-1 (3/5): streamSpeakContent 重写

`backend/internal/agent/react_runner.go::streamSpeakContent`：

- 旧签名 `(string, bool)` 二态：成功 / 失败
- 新行为：每次 chunk 后 `value, complete := scanJSONContentField(raw)`：
  - `!complete` (partial) → 推 partial 给前端 typewriter,继续等
  - `complete` → 推 final 一次,跳出循环
  - 30s 超时 / ctx-cancel / chunk Err → WARN + 返回 `("", false)` (新 caller 三态分流)

主循环移除 `indexOfJSONField` (死代码) + 取消对 inline escaping parse 的依赖。

### PR-1 (4/5): ActionSpeak caller 三态分流 (L408-471)

`backend/internal/agent/react_runner.go::case ActionSpeak`：

```go
streamed, complete := r.streamSpeakContent(ctx, out, messages)
if complete && streamed != "" {
    out.Content = streamed
    streamSucceeded = true
} else if complete && streamed == "" {
    slog.Warn("streamSpeakContent: LLM emitted empty content field; will retry via validateSpeak", ...)
    // streamSucceeded 保持 false, validateSpeak retry 接管
}
// !complete 路径: streamSpeakContent 已 WARN, 此处不再重复
```

行为契约：
- 真成功 → streamSucceeded=true (validateSpeak + stance/novelty/rebuttal guard 继续)
- 显式空 → streamSucceeded=false,但 streamSpeakContent 已收尾,validateSpeak fail → retry → Complete 拿新 content (与 LLM reject 路径同语义)
- 失败/超时 → streamSucceeded=false (现有 fallback 路径)

### PR-1 (5/5): 删除 `indexOfJSONField` 死代码

唯一 caller `streamSpeakContent` 已不用,直接删除（避免 stale code，AGENTS.md 习惯）。

### PR-2 (1/4): finishTrial detached verdictCtx

`backend/internal/courtroom/service.go::finishTrial`：

```go
// trialCtx 保留 — 给 DB writes + closing statements 用 (受 cancelCall 影响)
ctx, cancel, err := s.withCancel(ctx, session.SessionUUID)
if err != nil { return err }
defer cancel()
defer s.clearCancel(session.SessionUUID)

// v2.7 PR-2: 法官 verdict 必须 detached, 不被上游牵连
verdictCtx, vcancel := context.WithTimeout(context.Background(), 120*time.Second)
defer vcancel()
```

`JudgeFinalDecision` (L1585) + `GenerateVerdict` (L1642) 改用 `verdictCtx` 而不是 `ctx`。

借鉴 `agent/orchestrator.go:451` (`recordSideEffects`) 的同款 pattern。

### PR-2 (2/4): completeWithCancelRetry helper (orchestrator.go)

`backend/internal/agent/orchestrator.go`：新增 helper 函数 + IIFE 让 retry ctx 在 helper scope 内 cleanup:

```go
func (o *Orchestrator) completeWithCancelRetry(ctx, label, prompt, msgs, opts) (string, llm.Usage, error) {
    content, usage, err := o.llmClient.Complete(ctx, ...)
    if errors.Is(err, context.Canceled) {
        log.Printf("[%s] retried with detached ctx after context.Canceled", label)
        var (rContent string; rUsage llm.Usage; rErr error)
        func() {
            retryCtx, rc := context.WithTimeout(context.Background(), 90*time.Second)
            defer rc() // helper scope 内 IIFE cleanup
            rContent, rUsage, rErr = o.llmClient.Complete(retryCtx, ...)
        }()
        if rErr != nil { return "", llm.Usage{}, rErr }
        return rContent, rUsage, nil
    }
    return content, usage, err
}
```

**关键发现 (debug 历程)**: 一开始把 `defer rc()` 写在 `if errors.Is(...)` block 内,Go `defer` 按 **function scope** 不是 block scope,导致 retry ctx 在 JudgeFinalDecision return 后才 cleanup。改成 IIFE 让 defer 在 helper scope 内立刻 cleanup。

`GenerateVerdict` + `JudgeFinalDecision` 改用该 helper。

### PR-2 (3/4): runCrossExamRound clearCancel defer 补漏

`backend/internal/courtroom/service.go::runCrossExamRound` (L1225)：

```go
defer cancel()
defer s.clearCancel(session.SessionUUID) // v2.7 PR-2: 对称 finishTrial
```

之前缺失,导致 `activeCalls[sessionUUID]` 残留 stale cancel func 直到下次 `withCancel` 覆盖。补上对齐清理语义。

### PR-2 (4/4): 行为契约 retry hook

- **One-shot**: 仅 1 次 retry,不再无限（LLM 真挂要 propagate）
- **Cancelled only**: 仅 `errors.Is(err, context.Canceled)` 触发;`context.DeadlineExceeded` / network unreachable / JSON parse 都不 retry
- **Detached**: retry 用 `context.Background()` 派生,90s timeout
- **Backtrace**: log `"[GenerateVerdict] retried with detached ctx after context.Canceled"` 给运维定位
